RELEASE_TYPE: minor

This release adds `gs::from_lark`, which generates strings matching a grammar written in the syntax of the [Lark](https://lark-parser.readthedocs.io/en/stable/grammar.html) parsing library, the way `hypothesis.extra.lark.from_lark` does. The grammar is compiled by libhegel, which supports Lark's whole grammar language — rules, string and regex terminals with priorities, `%import` (with Lark's bundled `common`, `python`, `unicode` and `lark` grammars built in, and `.import_path(dir)` for your own), `%ignore`, `%declare`, `%override`, `%extend` and templates — and generates strings Lark's Earley parser accepts, with `%ignore`d whitespace and comments inserted where a lexer would skip them. Strings range up to 8192 characters by default and are biased toward the larger end; `.max_size(n)` and `.max_depth(n)` cap them, `.start(name)` picks the start rule, `.alphabet(characters)` constrains the characters regex terminals draw, and `.explicit(name, generator)` draws a terminal from a `text`, `from_regex`, `emails`, `urls` or `domains` generator instead (required for `%declare`d terminals). Grammar errors are reported at the first draw with Lark's diagnostics, or better ones where they exist. A grammar string is a single choice holding the string itself, so a saved failure survives edits to the grammar as long as the string still parses, and it shrinks through its derivation — repetitions deleted, nested rules hoisted, ignored text cut, terminals shortened — rather than by re-running the generator.
