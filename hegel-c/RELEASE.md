`hegel_pool_restore(ctx, tc, pool, variable_id)` puts back a variable that a consuming `hegel_pool_generate` removed from the pool, so a frontend can leave the pool as it was when the value drawn with it is thrown away unused, as a filter does with a rejected attempt. A variable that is not a consumed member of the pool is an argument error, and libhegel never puts a variable back on its own.

`hegel_tzdb_version(ctx, out_version)` reports the IANA time zone database release bundled in libhegel, such as `"2026e"`, as a static string, so a frontend can tell which zones and transitions the engine's forthcoming time zone generators will draw from. No generator uses the bundled database yet.

`hegel_timezone_resolve(ctx, name, civil, out)`, `hegel_timezone_offset_at(ctx, name, timestamp, out)` and `hegel_timezone_info(ctx, name, out)` query the bundled time zone database: the first classifies a wall-clock time in a zone as unique, in a gap or in a fold, with the offsets on either side and the instant it resolves to under the usual rule (a gap time read with the pre-transition offset, the earlier instant of a fold); the second reports the offset, DST flag and abbreviation in force at an instant; the third says whether a name is known, which primary zone it resolves to, its shrink rank and its feature tags. Names are matched exactly as the IANA database spells them, with `Etc/Unknown` as the zone whose offset is unknown. These are queries rather than draws, so a frontend can check a generated value without a capable native date library.

`hegel_generate_timezone(ctx, tc, spec, out_result)` draws an IANA time zone name from a `hegel_timezone_spec_t`: by default every bundled name with links such as `Asia/Calcutta` included and legacy names such as `EST5EDT` excluded, or an explicit list set with `hegel_timezone_spec_set_names`, with `hegel_timezone_spec_set_links`, `hegel_timezone_spec_set_legacy` and `hegel_timezone_spec_set_unknown` switching the link and legacy names and `Etc/Unknown`, and `hegel_timezone_spec_set_opaque` admitting a listed name the bundled database lacks as a zone the frontend evaluates itself. Half the draws are uniform over the allowed names and half weighted by the zones' feature tags, so a zone with a rare feature is drawn at a rate a short run reaches. A name shrinks down the rank ladder `hegel_timezone_info` reports, to `UTC` when it is allowed, and a stored name the spec no longer allows replays as the lowest-ranked allowed one.

`hegel_generate_zoned_datetime(ctx, tc, tz_spec, zoned_spec, out_value, out_zone)` draws a zone from a time zone spec and a wall-clock time in it within the bounds of a `hegel_zoned_spec_t`, reporting the civil fields, the offset, whether the wall time is unique, skipped or repeated with the offsets on either side, the fold and the instant. `hegel_zoned_spec_set_civil_bounds` and `hegel_zoned_spec_set_instant_bounds` bound the draw on the wall clock or the instant, `hegel_zoned_spec_set_precision` sets the unit the time of day is counted in, `hegel_zoned_spec_set_imaginary` chooses whether a skipped wall time is reported or moved to the first wall time after the gap, and `hegel_zoned_spec_set_ambiguous` chooses whether a repeated wall time means either instant, decided by a drawn fold, or always the earlier or the later. One draw in twenty on average targets a transition of the zone, so gap times, both folds and the exact boundary instants are reached; a value shrinks down the zone ladder and then toward 2000-01-01T00:00 within the bounds.
