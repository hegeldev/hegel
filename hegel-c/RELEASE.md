RELEASE_TYPE: minor

`hegel_pool_restore(ctx, tc, pool, variable_id)` puts back a variable that a consuming `hegel_pool_generate` removed from the pool, so a frontend can leave the pool as it was when the value drawn with it is thrown away unused, as a filter does with a rejected attempt. A variable that is not a consumed member of the pool is an argument error, and libhegel never puts a variable back on its own.

This release changes the signatures of `hegel_generate_time`, `hegel_generate_datetime` and `hegel_generate_date`. The first two take a `precision` argument, a `hegel_precision_t` from `HEGEL_PRECISION_NANOSECONDS` to `HEGEL_PRECISION_HOURS`, and draw a time of day that is a whole number of those units, so a frontend whose type holds microseconds or milliseconds draws exactly the values it can hold instead of truncating afterwards. `hegel_generate_date` takes a `hegel_date_options_t` handle, which may be NULL, from `hegel_date_options_new`, with `hegel_date_options_set_weekdays` and `hegel_date_options_set_months` restricting the draw to a bit set of weekdays or months (a drawn day is moved to the nearest allowed day inside the bounds rather than rejected, and bounds holding no allowed day are an argument error); release it with `hegel_date_options_free`.

```c
// before
hegel_generate_time(ctx, tc, min, max, &out);
hegel_generate_datetime(ctx, tc, min, max, &out);
hegel_generate_date(ctx, tc, min, max, &out);

// after
hegel_generate_time(ctx, tc, min, max, HEGEL_PRECISION_NANOSECONDS, &out);
hegel_generate_datetime(ctx, tc, min, max, HEGEL_PRECISION_NANOSECONDS, &out);
hegel_generate_date(ctx, tc, min, max, NULL, &out);
```

Passing `HEGEL_PRECISION_NANOSECONDS` and `NULL` keeps each draw's previous values. The date and time draws also target the calendar's own interesting values in one draw of twenty on average, so the leap days nearest the bounds, the year boundaries, the 2038 and 2106 overflow days, ISO week 53 and the last nanosecond of a day are reached by a short run.

It also bundles the IANA time zone database and adds draws of every date and time value the frontends had been building for themselves:

`hegel_tzdb_version(ctx, out_version)` reports the IANA release bundled in libhegel, such as `"2026e"`, as a static string, so a frontend that resolves zones with its own database can tell when the two differ. The engine decides what to generate from its own copy, identically on every machine, and the host library decides what the value means.

`hegel_timezone_resolve(ctx, name, civil, out)`, `hegel_timezone_offset_at(ctx, name, timestamp, out)` and `hegel_timezone_info(ctx, name, out)` query the bundled database: the first classifies a wall-clock time in a zone as unique, in a gap or in a fold (`hegel_timezone_kind_t`), with the offsets on either side and the instant it resolves to under the usual rule (a gap time read with the pre-transition offset, the earlier instant of a fold); the second reports the offset, DST flag and abbreviation in force at an instant; the third says whether a name is known, which primary zone it resolves to, its shrink rank and its feature tags as `HEGEL_TIMEZONE_TAG_*` bits. Names are matched exactly as the IANA database spells them, with `Etc/Unknown` as the zone whose offset is unknown. These are queries rather than draws, so a frontend can check a generated value without a capable native date library.

`hegel_generate_timezone(ctx, tc, spec, out_result)` draws an IANA time zone name from a `hegel_timezone_spec_t`: by default every bundled name with links such as `Asia/Calcutta` included and legacy names such as `EST5EDT` excluded, or an explicit list set with `hegel_timezone_spec_set_names`, with `hegel_timezone_spec_set_links`, `hegel_timezone_spec_set_legacy` and `hegel_timezone_spec_set_unknown` switching the link and legacy names and `Etc/Unknown`, and `hegel_timezone_spec_set_opaque` admitting a listed name the bundled database lacks as a zone the frontend evaluates itself. Half the draws are uniform over the allowed names and half weighted by the zones' feature tags, so a zone with a rare feature is drawn at a rate a short run reaches. The name is stored in the choice sequence and the database as written, so a saved failure means the same zone on every machine. A name shrinks down the rank ladder `hegel_timezone_info` reports, to `UTC` when it is allowed: real zones with a whole-hour offset and at most a simple daylight-saving rule come first, then the other real zones, then the `Etc/GMT` family and last the legacy names, so a failure shrinks to a zone a reader recognises; a stored name the spec no longer allows replays as the lowest-ranked allowed one.

`hegel_generate_zoned_datetime(ctx, tc, tz_spec, zoned_spec, out_value, out_zone)` draws a zone from a time zone spec and a wall-clock time in it within the bounds of a `hegel_zoned_spec_t`, reporting in a `hegel_zoned_datetime_t` the civil fields, the offset, whether the wall time is unique, skipped or repeated with the offsets on either side, the fold and the instant. `hegel_zoned_spec_set_civil_bounds` and `hegel_zoned_spec_set_instant_bounds` bound the draw on the wall clock or the instant, `hegel_zoned_spec_set_precision` sets the unit the time of day is counted in, `hegel_zoned_spec_set_imaginary` chooses whether a skipped wall time is reported or moved to the first wall time after the gap, and `hegel_zoned_spec_set_ambiguous` chooses whether a repeated wall time means either instant, decided by a drawn fold, or always the earlier or the later. One draw in twenty on average targets a transition of the zone, so gap times, both folds and the exact boundary instants are reached; a value shrinks down the zone ladder and then toward 2000-01-01T00:00 within the bounds.

`hegel_generate_timestamp(ctx, tc, min, max, precision, out)` draws an instant as a `hegel_timestamp_t` of seconds since the Unix epoch and nanoseconds, within the civil range of years ±999,999, shrinking toward 2000-01-01T00:00:00Z and targeting the Unix epoch, the 32-bit and 64-bit boundaries, the leap-second boundaries and the transitions of every bundled zone.

`hegel_generate_offset(ctx, tc, min_seconds, max_seconds, granularity, allow_unknown, out)` draws a UTC offset as a `hegel_offset_t` within ±25:59:59 that is a whole number of hours, quarter-hours, minutes or seconds (`hegel_offset_granularity_t`), shrinking toward zero and targeting the offsets any bundled zone has ever used, so `+05:45`, `+12:45` and `-00:44:30` appear. With `allow_unknown` the draw can yield the unknown offset (RFC 3339's `-00:00`), reported with `known` false, which shrinks to a known one.

`hegel_generate_duration(ctx, tc, min, max, precision, out)` draws a signed duration as a `hegel_duration_t` of `i64` seconds and nanoseconds of the same sign, shrinking toward zero.

`hegel_generate_span(ctx, tc, spec, out)` draws a calendar span, a `hegel_span_t` with a value for each of years, months, weeks, days, hours, minutes, seconds, milliseconds, microseconds and nanoseconds, from a `hegel_span_spec_t` built with `hegel_span_spec_new`, `hegel_span_spec_set_unit_bounds` for each unit to enable and `hegel_span_spec_set_sign`, which picks one sign for every unit (`HEGEL_SPAN_SIGN_UNIFORM`, as a jiff `Span` or Temporal `Duration`), a sign per unit (`HEGEL_SPAN_SIGN_MIXED`, as a java `Period`) or magnitudes only (`HEGEL_SPAN_SIGN_NONNEGATIVE`); release the spec with `hegel_span_spec_free`. A span shrinks to all zeros.

Every new draw prints in the engine's own diagnostics as an RFC 9557 string, such as `2024-03-10T02:30:00-04:00[America/New_York][gap]`, with `[gap]` or `[fold=N]` appended to a skipped or repeated wall time, `-00:00` for an unknown offset and `Z[Etc/Unknown]` for the unknown zone, so a counterexample reads the same from every frontend.
