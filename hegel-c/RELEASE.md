RELEASE_TYPE: minor

This release adds grammar-based string generation. `hegel_grammar_new` compiles a grammar written in the syntax of the [Lark](https://lark-parser.readthedocs.io/en/stable/grammar.html) parsing library into a `hegel_grammar_t` handle (freed with `hegel_grammar_free`), taking the start rule, size and depth caps, an alphabet string generator for the regex terminals, the names of the terminals whose values the binding supplies (each occurrence in a drawn string is the placeholder marker `hegel_grammar_placeholder` reports, for the binding to replace with a value of its own), and an import callback through which the binding supplies `%import`ed grammar files (Lark's bundled `common`, `python`, `unicode` and `lark` grammars are built in). `hegel_generate_grammar` then draws a string of the grammar into a `hegel_generate_string_result_t`, as `hegel_generate_string` does, under a cap of the draw's own below the grammar's when the binding passes one (a placeholder marker counts as no characters toward either, so a binding keeps the string with its values spliced in under the user's cap by drawing again under a smaller one), and returns `HEGEL_E_ASSUME` when it gives up on a string that lexes back as its tokens, which rejects the test case. The engine supports the whole grammar language and generates strings Lark's Earley parser accepts, inserting `%ignore`d terminals where a lexer would skip them and avoiding strings Lark's basic lexer would read differently where the grammar allows; the design is described in the module documentation of `src/native/lark/generate.rs`, and `docs/grammar-strings.md` maps how a grammar string lives in the choice sequence. A grammar string is a single string choice holding the string itself, constrained by the grammar: a replay parses the stored string, replacing one the grammar no longer derives with its simplest string, and the shrinker edits it through its derivation.

Strings drawn from a `hegel_string_generator_regex` generator are now recorded the same way: as one string choice holding the string, constrained by the pattern. A replay keeps a stored string as long as it still matches the pattern, and the shrinker edits it within the pattern instead of re-running the generator, so a `\d` shrinks to `0` rather than to the smallest digit the old choice order happened to reach. Failures saved by earlier versions were recorded as the generator's individual draws and no longer replay through this generator; they are dropped from the database the way any stale entry is.
