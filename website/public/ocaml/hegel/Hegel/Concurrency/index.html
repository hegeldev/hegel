Module Hegel.Concurrency

Concurrency capabilities for concurrent stateful tests.

Choose how to execute a concurrent state machine. Hegel uses threads by default.

Pass a backend as ~concurrency to Stateful.run_concurrent or to the run of a module%hegel_concurrent_state_machine:

let%hegel_test counter tc =
  Stateful.run_concurrent
    tc
    (module Counter)
    ~init:(Atomic.make 0)
    ~concurrency:Concurrency.threads
    ~max_concurrency:4
;;

On OxCaml, hegel.jane.concurrent wraps a Jane Street Concurrent.t as a backend.

type 'ctx t

How a concurrent state machine executes its rules. Hegel chooses the concurrency level between the run's min_concurrency and max_concurrency.

val threads : unit t

Runs rules on threads in the calling domain, with () as their context. The threads are reused until the run ends.

val domains : unit t

Runs rules in parallel on threads spread across OCaml domains, with () as their context. The workers are reused until the run ends.

type outcome = (exn * Stdlib.Printexc.raw_backtrace) option

None on success, or its exception and backtrace.

val create : spawn_join_n:(n:int -> f:('ctx -> int -> outcome) -> outcome list) -> 'ctx t

create ~spawn_join_n runs the test's concurrent bodies through your scheduler. Hegel supplies n and f. Call f ctx i once for every index from 0 to n - 1. Wait for every body to finish and return their outcomes in index order. Exceptions raised by a body should be its outcome.

Pass the result as the test's ~concurrency argument.
