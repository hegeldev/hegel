RELEASE_TYPE: patch

This patch adds `from_lark()`, which generates strings of a grammar written in the syntax of the [Lark](https://lark-parser.readthedocs.io/en/stable/grammar.html) parsing library, as the Rust library's `from_lark` does. The grammar is parsed and its strings generated by Hegel's engine, so Lark need not be installed. `start` picks the rule to generate, `explicit` maps terminal names to generators of strings that supply those terminals' values (required for a terminal the grammar `%declare`s), `alphabet` restricts the characters the terminals' patterns produce, `max_size` and `max_depth` cap the length and nesting of the strings, and `import_path` is the directory `%import`ed grammar files are read from. The 0.2.0 changelog described `from_lark()` as following this Python's Unicode version, though no `from_lark()` existed then; it now exists, and does.

```python
expression = tc.draw(
    gs.from_lark(
        """
        ?start: sum
        ?sum: product | sum "+" product
        ?product: atom | product "*" atom
        ?atom: NUMBER | "(" sum ")"
        %import common.NUMBER
        %import common.WS
        %ignore WS
        """
    )
)
```

It also gives `Settings` an `unbounded_choices` field (default `False`), the engine setting that lifts the limit of 2**20 choices per test case, for long-running test cases such as a concurrent state machine driven for hours. `Settings` now mirrors every engine setting, so a profile that sets `unbounded_choices` (one registered by another Hegel library in the same process, say) is no longer reset to the default when a Python test runs with it.

`TestCase.clone()` and `TestCase.set_worker()` are now public, so a test can draw from several threads: give each thread its own clone, which draws from an independent choice stream of the same test case, and optionally attribute its output to a numbered worker. They were previously private, used only by the concurrent stateful runner.

Draws may now nest as deeply as Python's recursion limit allows. A test case used to be abandoned once its draws nested 100 deep, which a `recursive()` generator at its default `max_depth` of 32 could reach, and a draw from a `deferred()` generator nested more than 64 deep rejected the test case. Both fixed limits are gone: a test case is abandoned as too large only when its draws nest so deeply that the interpreter's recursion limit (`sys.getrecursionlimit()`) is within 200 frames, rather than failing with a `RecursionError`. A `deferred()` definition that only refers back to itself therefore now fails with `FailedHealthCheck` rather than `Unsatisfiable`.

`text()` and `binary()` without a `max_size` now leave the maximum to the engine, which applies the default every Hegel library shares (100, or `min_size + 100` when `min_size` is larger), rather than computing it in Python. Their reprs no longer show a `max_size` that was not given. `filter()` and the filtered `values_consumed()` of stateful pools take the number of attempts before rejecting from the engine too.

The pytest plugin gains `--hegel-setting KEY=VALUE`, which sets any setting by its `hegel.toml` key with the value spelled as in `hegel.toml` (`--hegel-setting test_cases=1000`, `--hegel-setting suppress_health_check=too_slow,filter_too_much`), and may be repeated. The engine parses every option's value, including those of `--hegel-seed`, `--hegel-verbosity`, `--hegel-derandomize` and `--hegel-database`, so a bad value is a usage error naming what the setting accepts.
