RELEASE_TYPE: minor

This release makes the string generators follow the host's Unicode version. A binding sets it once with the new `hegel_set_unicode_version`, passing a version number such as `"15.1.0"` (Python's `unicodedata.unidata_version`, say): the General Categories a text alphabet is built from, and the `\w`, `\d` and `\s`, word boundaries and case-insensitive matching of regex and grammar patterns, then follow the Unicode tables of that version rather than the engine's newest. A string drawn for a host whose Unicode is older than the engine's is classified as that host classifies it, where it could previously contain a character the host did not know yet or put in another category. The engine has tables for Unicode 14.0.0 to 17.0.0, the versions of CPython 3.11 to 3.15; the empty string selects its newest tables, which a version newer than them uses too, and a version it has no tables for is an invalid argument. The version is read when a generator or grammar is built, so a binding that never sets it gets the engine's newest tables, as before.

This release also accepts `\z` in regex patterns, the end-of-string anchor Python 3.14 added to `re` as a spelling of `\Z`, and rejects as an invalid argument a float draw whose bounds leave only an infinity while infinities are disallowed (a `min_value` of `inf` or a `max_value` of `-inf`, possibly after stepping an exclusive bound), which used to fail as an internal error.

It also fixes a shrinking regression introduced in 0.46.0. A run that reports a single failure shrinks only the smallest failure it found, but shrinking that failure can run into a different failure with a smaller example than any seen before, and the run then reported that example without shrinking it. Such a failure is now shrunk before it is reported, so the reported failure is minimal again.
