RELEASE_TYPE: minor

This release changes the signatures of `hegel_generate_time`, `hegel_generate_datetime` and `hegel_generate_date`. The first two take a `precision` argument, a `hegel_precision_t` from `HEGEL_PRECISION_NANOSECONDS` to `HEGEL_PRECISION_HOURS`, and draw a time of day that is a whole number of those units, so a frontend whose type holds microseconds or milliseconds draws exactly the values it can hold instead of truncating afterwards. `hegel_generate_date` takes a `hegel_date_options_t` handle, which may be NULL, from `hegel_date_options_new`, with `hegel_date_options_set_weekdays` and `hegel_date_options_set_months` restricting the draw to a bit set of weekdays or months (a drawn day is moved to the nearest allowed day inside the bounds rather than rejected, and bounds holding no allowed day are an argument error); release it with `hegel_date_options_free`.

```c
// before
hegel_generate_time(ctx, tc, min, max, &out);
hegel_generate_datetime(ctx, tc, min, max, &out);
hegel_generate_date(ctx, tc, min, max, &out);

// after
hegel_generate_time(ctx, tc, min, max, HEGEL_PRECISION_NANOSECONDS, &out);
hegel_generate_datetime(ctx, tc, min, max, HEGEL_PRECISION_NANOSECONDS, &out);
hegel_generate_date(ctx, tc, min, max, NULL, &out);
```

Passing `HEGEL_PRECISION_NANOSECONDS` and `NULL` draws from the same set of values as before. Which of them a short run reaches has changed: the date and time draws now target the calendar's own interesting values in one draw of twenty on average, so the leap days nearest the bounds, the year boundaries, the 2038 and 2106 overflow days, ISO week 53 and the last nanosecond of a day are reached by a short run.

It also bundles the IANA time zone database and adds draws of every date and time value the frontends had been building for themselves:

`hegel_tzdb_version(ctx, out_version)` reports the IANA release bundled in libhegel, such as `"2026e"`, as a static string. The bundled database is what every zone draw and query reads until a zone source (described at the end of these notes) is set, and it stays the source of the zones' shrink order and feature tags after that.

`hegel_timezone_resolve(ctx, name, civil, out)`, `hegel_timezone_offset_at(ctx, name, timestamp, out)` and `hegel_timezone_info(ctx, name, out)` query the process's default zone source, which is the bundled database unless `hegel_set_default_zone_source` changed it: the first classifies a wall-clock time in a zone as unique, in a gap or in a fold (`hegel_timezone_kind_t`), with the offsets on either side and the instant it resolves to under the usual rule (a gap time read with the pre-transition offset, the earlier instant of a fold); the second reports the offset, DST flag and abbreviation in force at an instant; the third says whether a name is known, which primary zone it resolves to, its shrink rank and its feature tags as `HEGEL_TIMEZONE_TAG_*` bits. Names are matched exactly as the zone source spells them (the bundled database as IANA does), with `Etc/Unknown` as the zone whose offset is unknown. These are queries rather than draws, so a frontend can check a generated value without a capable native date library.

`hegel_generate_timezone(ctx, tc, spec, out_result)` draws a time zone name from a `hegel_timezone_spec_t`, a handle made by `hegel_timezone_spec_new` and released with `hegel_timezone_spec_free`: by default every name of the zone source with links such as `Asia/Calcutta` included and legacy names such as `EST5EDT` excluded, or an explicit list set with `hegel_timezone_spec_set_names`, with `hegel_timezone_spec_set_links`, `hegel_timezone_spec_set_legacy` and `hegel_timezone_spec_set_unknown` switching the link and legacy names and `Etc/Unknown`, and `hegel_timezone_spec_set_opaque` admitting a listed name the zone source lacks as a zone the frontend evaluates itself. The setters can be called in any order: each reports only a bad argument of its own, and `hegel_timezone_spec_validate` reports what a draw from the spec as it stands would reject, such as a listed name the zone source lacks, so a frontend can report a bad generator where it is built rather than at its first draw. Half the draws are uniform over the allowed names and half weighted by the zones' feature tags, so a zone with a rare feature is drawn at a rate a short run reaches. The name is stored in the choice sequence and the database as written, so a saved failure means the same zone on every machine. A name shrinks down the rank ladder `hegel_timezone_info` reports, to `UTC` when it is allowed: real zones with a whole-hour offset and at most a simple daylight-saving rule come first, then the other real zones, then the `Etc/GMT` family and last the legacy names, so a failure shrinks to a zone a reader recognises; a stored name the spec no longer allows replays as the lowest-ranked allowed one.

`hegel_generate_zoned_datetime(ctx, tc, tz_spec, zoned_spec, out_value, out_zone)` draws a zone from a time zone spec and a wall-clock time in it within the bounds of a `hegel_zoned_spec_t`, a handle made by `hegel_zoned_spec_new` and released with `hegel_zoned_spec_free`, reporting in a `hegel_zoned_datetime_t` the civil fields, the offset, whether the wall time is unique, skipped or repeated with the offsets on either side, the fold and the instant. `hegel_zoned_spec_set_civil_bounds` and `hegel_zoned_spec_set_instant_bounds` bound the draw on the wall clock or the instant (a spec given both is an argument error, which `hegel_zoned_spec_validate` and every draw report), `hegel_zoned_spec_set_precision` sets the unit the time of day is counted in, `hegel_zoned_spec_set_imaginary` chooses whether a skipped wall time is reported or moved to the first wall time after the gap, and `hegel_zoned_spec_set_ambiguous` chooses whether a repeated wall time means either instant, decided by a drawn fold, or always the earlier or the later. One draw in twenty on average targets a transition of the zone, so gap times, both folds and the exact boundary instants are reached; a value shrinks down the zone ladder and then toward 2000-01-01T00:00 within the bounds. A drawn zone with no value in the bounds rejects the test case with `HEGEL_E_ASSUME`, and bounds in which no allowed zone has a value are an argument error.

`hegel_generate_zoned_datetime_for_zone(ctx, tc, source, name, zoned_spec, out_value)` makes the same draw in a zone the caller names, resolved against `source` or, when that is NULL, the default zone source. It records what `hegel_generate_zoned_datetime` records after its zone, so a frontend that cannot be called back while the engine draws can draw the name with `hegel_generate_timezone`, supply that zone's data, and then draw the value, and a frontend whose user fixed the zone need not build a one-name spec.

`hegel_generate_timestamp(ctx, tc, min, max, precision, out)` draws an instant as a `hegel_timestamp_t` of seconds since the Unix epoch and nanoseconds, within the civil range of years ±999,999, shrinking toward 2000-01-01T00:00:00Z and targeting the Unix epoch, the 32-bit and 64-bit boundaries, the leap-second boundaries and the transitions of every bundled zone.

`hegel_generate_offset(ctx, tc, min_seconds, max_seconds, granularity, allow_unknown, out)` draws a UTC offset as a `hegel_offset_t` within ±25:59:59 that is a whole number of hours, quarter-hours, minutes or seconds (`hegel_offset_granularity_t`), shrinking toward zero and targeting the offsets any bundled zone has ever used, so `+05:45`, `+12:45` and `-00:44:30` appear. With `allow_unknown` the draw can yield the unknown offset (RFC 3339's `-00:00`), reported with `known` false, which shrinks to a known one.

`hegel_generate_duration(ctx, tc, min, max, precision, out)` draws a signed duration as a `hegel_duration_t` of `i64` seconds and nanoseconds of the same sign, shrinking toward zero.

`hegel_generate_span(ctx, tc, spec, out)` draws a calendar span, a `hegel_span_t` with a value for each of years, months, weeks, days, hours, minutes, seconds, milliseconds, microseconds and nanoseconds, from a `hegel_span_spec_t` built with `hegel_span_spec_new`, `hegel_span_spec_set_unit_bounds` for each unit to enable and `hegel_span_spec_set_sign` (in either order, with `hegel_span_spec_validate` reporting a spec no draw could satisfy), which picks one sign for every unit (`HEGEL_SPAN_SIGN_UNIFORM`, as a jiff `Span` or Temporal `Duration`), a sign per unit (`HEGEL_SPAN_SIGN_MIXED`, as a java `Period`) or magnitudes only (`HEGEL_SPAN_SIGN_NONNEGATIVE`); release the spec with `hegel_span_spec_free`. A span shrinks to all zeros.

`hegel_format_date`, `hegel_format_time`, `hegel_format_datetime`, `hegel_format_timestamp`, `hegel_format_offset`, `hegel_format_duration`, `hegel_format_span` and `hegel_format_zoned_datetime` return the text of a value as a `hegel_owned_string_t`, so a counterexample reads the same from every frontend and no frontend writes the rules again. Dates and times are ISO 8601 (`2024-03-10`, `02:30:00.5`, a year outside 0 to 9999 as `+010000` or `-000001`), a timestamp is its UTC datetime and `Z`, an offset is `+05:30` or `-00:44:30` with `-00:00` for the unknown one, a duration is `PT1H30M5.5S`, a span is `1y 2mo 3d` (`-3d 4h` when every unit is negative, `-3d +4h` when the signs differ), and a zoned datetime is an RFC 9557 string such as `2024-03-10T02:30:00-04:00[America/New_York][gap]`, with `[gap]` or `[fold=N]` appended to a skipped or repeated wall time and `Z[Etc/Unknown]` for the unknown zone. The engine's own diagnostics print the new draws the same way.

It also adds zone sources, so that zone draws and queries can target and classify against the time zone data the code under test uses rather than the bundled copy. `hegel_zone_source_new(ctx, out_source)` makes an empty `hegel_zone_source_t` (and `hegel_zone_source_bundled` a handle on the bundled database), released with `hegel_zone_source_free`. A source takes a zone's data as a TZif file (`hegel_zone_source_add_tzif`), as fields in a `hegel_zone_data_t` (`hegel_zone_source_add_zone`), or from an offset oracle the engine probes over a range of years (`hegel_zone_source_add_oracle`, with a `hegel_zone_oracle_t` of `hegel_zone_offset_fn_t` and `hegel_zone_next_transition_fn_t` callbacks), holding the last offset or inferring a yearly rule beyond them as the caller chooses with `hegel_zone_after_t`. `hegel_zone_source_add_link` adds a link, and `hegel_zone_source_declare` with `hegel_zone_source_set_loader` declares names whose data a `hegel_zone_loader_t` callback supplies the first time a draw or query needs it, so only the zones drawn are loaded. `hegel_zone_source_set_loader` also takes a `hegel_zone_loader_release_t`, which the engine calls exactly once with the loader's `user_data` when it drops the loader (on its replacement or removal, when the last reference to the source goes, or when the call fails), so a frontend can free the loader's state there. `hegel_set_default_zone_source` sets the process-wide default, the bundled database until it is set: a time zone spec reads it when `hegel_timezone_spec_new` creates the spec and keeps that source whatever the default becomes later, and the queries read it at each call. `hegel_timezone_spec_set_source` attaches a source to one spec, overriding the default. `hegel_timezone_resolve_in`, `hegel_timezone_offset_at_in` and `hegel_timezone_info_in` query a given source. A name the bundled catalogue has keeps its flags, tags and rank whatever source supplies its data; a name it lacks is a real zone with the last rank and tags computed from its data. A callback returns an `int32_t`, 0 for success and anything else for failure, with its message set by `hegel_context_set_error`, and the draw, query or upload that called it fails with that message as an argument error. `hegel_zone_source_set_version` and `hegel_zone_source_version` record and read a source's release, which failure output does not report; `hegel_tzdb_version` stays the bundled release. With no source set, every draw and query behaves as it did against the bundled database.
