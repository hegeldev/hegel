RELEASE_TYPE: minor

This release makes the engine responsible for printing a test case's output, which keeps the memory of a long-running test case flat at every verbosity and lets a verbose run print a state machine round by round.

A test case's document is now printed by the engine, through the output callback of its run (or of `hegel_test_case_from_blob`), as soon as nothing can change it: a verbose run streams it, and a test case stamped for capture keeps it, with its diagnostic, as the report of its failure. Frontends migrate as follows:

- `hegel_test_case_should_capture` is replaced by `hegel_test_case_wants_output`, which says whether the engine will use what the test case prints, and the new `hegel_test_case_wants_detail`, which says whether it will use a failure's full diagnostic. Print draws and notes only when the first is true, and render a stack trace or backtrace only when the second is. A quiet run prints and keeps nothing, but its stamped test cases still want output, so a frontend raising a failure's exception keeps the one from the latest failing test case that wanted output.
- `hegel_mark_complete` takes a failing test case's `summary` and `detail` after its `origin`: `summary` is one line (the error's type and message, the location in the test when known), printed after the test case in a verbose run; `detail` is the complete diagnostic, printed at debug verbosity and kept for the failure report. All three are NULL for any other status. `hegel_mark_complete` now rejects a call that leaves out what the engine needs — a failure without an origin, a summary when output is wanted, a detail when detail is wanted, a summary with a newline, or any of them for a test case that did not fail — and a rejected call completes nothing. It also rejects a call on a clone: only the test case's root handle completes it, so that everything the engine prints for a test case happens on one thread, in order. A clone's completion used to be accepted, the first call from any handle winning.
- Read what each failure's test case printed from the new `hegel_failure_output`, and its detail from the new `hegel_failure_diagnostic`, instead of keeping captures per origin, and show them with the failure.
- A NULL output callback now means no destination: the engine prints nothing and renders as it does at normal verbosity, so verbose and debug cost nothing when nobody would see them, while the failure report keeps its data. Pass the new `hegel_output_stderr` to write to stderr; a host that cannot take a function's address (WebAssembly) gets it from `hegel_output_stderr_callback`.
- `hegel_printer_resolve` and `hegel_printer_value` now refuse a test case's printer; documents from `hegel_printer_new` are unchanged. Completing a test case seals its document.
- A verbose run's "Test case stopped" lines are printed by the engine.
- The output callback of `hegel_run_start` and `hegel_run_start_blob` must stay valid until `hegel_run_free` returns (freeing a run completes a test case still in flight, which may print), and that of `hegel_test_case_from_blob` until the test case completes.
- The WebAssembly module imports a third host function, `hegel_host.stderr_write(ptr, len)` (`hegel_host_stderr_write` in the static archive), which `hegel_output_stderr` writes through: it receives the bytes of each line, the text and its newline possibly in separate calls.
- `hegel_test_case_printer` now refuses a `max_width` different from the document's once the engine has printed part of the test case's output, since the rest would be laid out at a different width.

It also fixes the layout of a line that follows a block ending in a hard break: when that line started with a breakable (or another token whose layout waits for what follows), it could break as if it were still indented by the block.
